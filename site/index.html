WHAT IT DOES 01 — 03

軟體工程開始時，
自動載入交付規則。

當 Agent 開始軟體開發、修 bug、審查程式碼、處理 PR 或部署時，JT Harness 會提供一致的交付規則，協助追蹤工作並確認交付條件。

01 / TRACK

任務有跡可循

先在 Linear 對應 issue：小任務寫清處理方式與驗收；跨 issue 功能連結共用 spec。完成後記錄結果、PR、審查、檢查與合併狀態。

02 / ROUTE

工具各司其職

Coolify 資源使用 Coolify Skill；Hetzner Cloud 與 Storage Box 使用 Hetzner Skill。

03 / REVIEW

通過審查門檻

Codex 與 CodeRabbit 各進行一次完整 current-head 審查；程式碼、測試、腳本、由 repo/plugin 載入的操作型 agent 指示／政策，或任何設定 PR 必須另完成 Pstack interrogate 與 no-comments。純文件／內容 PR 確認沒有程式碼、操作型指示／政策或設定變更後記錄 Pstack 不適用，並完成內容 audit：對照 canonical repo source 或權威來源核對事實、驗證連結與命令／檔案範例，每次內容 audit 都須記錄 changed paths、claim/source pairs、link/example 結果、格式或頁面佈局變更的渲染輸出證據，及已審查 commit SHA。格式或頁面佈局變更時檢查渲染結果；該 commit 後若文件／內容路徑再變更，合併前重做對應 audit 並更新證據。純媒體 PR 完成媒體驗收。Codex 或 CodeRabbit 明確回報錯誤、rate／usage limit 或審查完成但無結果時，記錄該 reviewer 的例外，不重試或要求替代；另一 reviewer 仍須完整 current-head 審查。其他失敗、跳過或不完整結果不算通過。合併前必須解決 Codex 與 CodeRabbit 的可採取行動 findings 並驗證修正。Pstack 的可採取行動 findings 必須解決或明確駁回。修正 findings 後，未被忽略的 reviewers 須完成差異確認；不重跑未變範圍的完整審查。若兩者都依例外忽略，Pstack 適用的 PR 仍須完成 Pstack 審查，純文件／內容 PR 須完成內容 audit，純媒體 PR 須完成媒體驗收。本機全專案 lint 必須通過；最新提交的必要檢查通過且 GitHub 可合併後，依規則合併。交付用 PR 不應該開成草稿（草稿不會觸發 Codex 與 CodeRabbit 自動審查）；如果已經開了草稿，要立刻轉成 ready；ready PR 沒有自動審查時，依規則各請求一次。GitHub 實際阻擋時記錄原因，不繞過平台限制。僅審查或明確禁止合併的工作不合併。

GET STARTED INSTALL

選擇安裝平台。

從官方儲存庫安裝；新版本會發布在 GitHub Releases。

01 / CODEX Codex

在終端機加入 JurisLM marketplace，並安裝插件：

codex plugin marketplace add https://github.com/jurislm/jt-harness-plugin --ref main
codex plugin add jt-harness-plugin@jurislm-jt-harness

安裝或更新後，開啟新的 Codex session 以載入 Skill。

02 / CURSOR Cursor
  1. 開啟 Customize → Plugins。
  2. 選擇 From GitHub Repository。
  3. 輸入 https://github.com/jurislm/jt-harness-plugin 並安裝 jt-harness-plugin。

更新後重新載入 Cursor，並確認 using-jt-harness Skill 已出現。

SCOPE WHAT IT IS

這是一個 Skill，
不是另一套服務。

JT Harness 的 Skill 會自動觸發並提供交付規則；若目前主機已安裝，工程方法優先使用官方 Pstack。Pstack interrogate 與 no-comments 適用於程式碼、測試、腳本、操作型 agent 指示／政策或任何設定 PR；純文件／內容與非執行媒體 PR 確認沒有上述變更後記錄不適用，並完成內容 audit 或媒體驗收。JT 專注於交付政策，不複製另一套方法框架。main/root checkout 僅供任務開發唯讀：工作目錄乾淨且更新安全時，可用 git pull --ff-only 更新；不得在該 checkout 編輯任務檔案、提交任務變更或直接推送開發變更。閱讀完整交付規則。

  • ✓ Codex 與 Cursor 的軟體工程交付規則
  • ✓ Linear 追蹤、平台 Skill 路由、審查與合併規則
  • — 不包含 MCP server、slash command、OAuth 或 hosted endpoint
  • — 不發布 npm package；版本透過 GitHub Releases 發布
  • ✓ 授權採用 MIT License
